The existing classifier discarded native reason; this does not prove bad credentials,
a banned phone or malformed phone. The prior startup deadlock is resolved on device.
Dpaste POST 201 / exact raw GET 200 / diagnosticUpload succeeded are device evidence.

Google master exchange and Photos token redemption succeed. Identity verification
returns HTTP 400 on fresh connect and saved retry. Credential remains saved. The
same Photos request builder sends protobuf Content-Type and Android Photos client
headers to the JSON OpenID endpoint. Correct this request envelope, preserving the
same access token and strict immutable sub requirement. Header correction is source
evidence, not proof of the HTTP 400 cause or completed Google linking.

Record closed native auth and OAuth error names; never persist raw provider messages,
phone digits, email, credential strings, response bodies or private paths. Unknown
messages stay unknown. TDLib error 406 must not be processed or displayed as raw prose.
International phone normalization/validation must not guess country codes.
Sources: pinned td_api.tl / AuthManager.cpp at
https://github.com/tdlib/td/tree/42e6a5259551178d1dab54a22ad96d14bd906e20/td ;
https://developers.google.com/identity/openid-connect/openid-connect .

Implementation: normalize international phone numbers (Unicode decimal digits and
common formatting), reject missing country code without guessing, send null default
phone settings, retain the input on failure, and record only closed native rejection
names. Never process TDLib 406 messages. Specific phone/API/rate-limit causes now
have useful explanations. Google identity GET uses JSON headers and app User-Agent.
Fresh connect now reuses the access token already redeemed successfully instead of
discarding it and immediately authenticating again. Saved credentials still refresh;
refresh failures carry their actual googleAuthenticate stage and are not mislabeled
as userinfo failures. Closed Google reasons only; arbitrary auth response prose is
removed from credential-rejection descriptions. Immutable same-token subject
verification remains required.

Important limit: previous googleIdentity traces wrap both internal authentication
and userinfo; HTTP 400 alone does not establish which endpoint rejected the request.
Header correction and avoiding redundant fresh authentication are source fixes, not
proof that Google accepts identity requests. Phone native 400 likewise needs the next
device report to identify its safe rejection name. Published version remains 2.1;
2.2 is pending, with no cloud build dispatched in this batch.
