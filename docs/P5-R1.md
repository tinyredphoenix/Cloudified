## R1-A — coordinator/recovery and safe commands

1. Separate a small owned command/producer coordinator from view assembly where
   useful; avoid another thousand-line monolith or a second queue/DB. Establish
   command-in-progress/generation state BEFORE the first await. Serialize conflicting
   per-provider commands; recheck mapping/generation after awaits. Own every running
   task until it joins; no replacement producer while the old one can still plan.
2. Recover providers independently/concurrently. After a fresh verified mapping or
   reconnect, call the real adapter.recover before marking it ready/enabling work.
   Preserve enabled preference independently of canRun. A failed provider stays
   unavailable with its own safe reason while the other runs. Enumerate all selected
   AND deselected retained mappings through destinationInventoryPage; page retained
   transfers and consult bindings. Missing credentials/profile, native uncertainty
   or incomplete recovery must keep ownership/cleanup gated, never imply success.
   Reattempt readiness-dependent recovery only on real relevant events or explicit
   reconnect, with one coalesced in-flight request; no timer/polling loop.
3. For credential/channel/policy changes: freeze that provider's source admission,
   disable via engine, then settle/join its worker and inspect durable/native holds.
   Unknown sends block credential/profile deletion or replacement; display settling
   old mapping and allow the other destination to continue. Use adapter.close for
   actual Telegram consumer/client close/join. Recreate its client+adapter+one set
   of observers only after verified native closure; never reuse finished streams,
   discard a live owner, delete DB keys or pretend app unlink is Telegram logout.
   Support truthful app unlink/reconnect; an actual account-switch flow requires
   explicit auth/logout semantics and fresh verified mapping, not merely new API
   credentials. Report unsupported switching clearly if a provider API is needed.
4. Use bounded TDLibClient.updates subscription for real authorization changes
   before mapping (session allows two subscribers including the adapter). No fake
   ready state from credentials alone. Surface actual native action requirements;
   preserve the password exactly, secure API hash input, clear secret fields after
   completion/dismissal. Match Google token help/label to GoogleTokenExchange and
   pinned PhotosBackup source; do not invent a normal Photos OAuth/browser flow.
5. Prevent command failure from disappearing in try?. Display a distinct provider
   failure, persist a safe event, and offer relevant action; a failed write retains
   a bounded in-memory fallback visibly available in Logs/attention state. Never
   log credentials, raw NSError prose, paths or native JSON. Use actual build/version
   metadata for ledger events, not a fixed prior commit hash.

## R1-B — source admission and requested drains

6. Prompt for genuine PhotoKit authorization on first explicit Back Up. Refresh
   metadata discovery for new assets/changed permissions on subsequent explicit
   backups. Reuse canonical IDs and persisted currentLibraryScan when resuming an
   interrupted drain. Reset the appropriate cursor when scan/mapping/policy changes;
   do not invent a scan UUID or silently skip newly added destination obligations.
7. Own one finite drain at a time with BOTH runnable adapters supplied together.
   Keep a separate bounded, demand-driven source producer; allow the fast lane to
   progress while the other is transferring within a small explicit credit bound.
   No unbounded source backlog, hashing all originals first, busy retry/polling loop,
   per-provider retry loop or child worker dropped on cancellation. Coalesce producer
   credit-ready/drain events without the empty-batch invalidation loop. A failed
   provider is isolated/suspended for its own cause; it does not end source admission
   or ready uploads for the healthy provider. Clear flags on every exit.
8. Keep explicit user backup intent separate from UI subscriptions. Recovery/native
   events may resume that requested drain after real recovery, without starting a
   backup the user did not request. Retain actual LaneResult.nextWake values for P6's
   single deadline scheduler; no new automatic attempt budget or resend of unknown
   work. Source Retry must replan the exact canonical asset/provider; job Retry only
   calls Core when state/holds allow an explicit new cycle. Expose rejection reasons.
9. Live Photo edits must preserve the actual enabled preference, freeze/join old
   planner work, disable/settle Google, require no retained inputs, invalidate current
   aliases, freeze new policy and reset coverage admission before enabling it again.
   Architect clarification: no old alias may count Saved; demand admission replans
   the new frozen generation without hashing the entire library first (D38).
   Telegram keeps full originals. Errors leave the transition safely disabled with
   a visible reason; old coverage cannot reappear after invalidation.

## R1-C — truthful bounded status, logs and resource ownership

10. Display simultaneous Google and Telegram current byte/phase/attempt information
    independently, keyed by actual job/mapping. Merge retained native status using
    destinationID/jobID, showing old-mapping settlement separately. Derive attempts
    from Ledger.job, never hard-code 1. Show waiting/recovery/unavailable status and
    ledger totals; Complete must mean confirmed required coverage, with disabled
    incomplete work explicitly identified. Preserve last good state on read failure
    and show the failure; never turn a DB error into "no failures" or fake progress.
11. Implement real bounded keyset pages + next-page controls for failures (job and
    source cursors independently), Logs and run selection. Query immediately on
    filter changes; coalesce refreshes <=2 Hz and reject stale query generations.
    Keep memory bounded when paging; expose pruned diagnostic history accurately.
    System includes actual system+source events without inventing EventOrigin.core.
    Maintain stable unique alias/provider/asset row identity. Show real nullable
    capture date/duration from PhotoKit/source recipe; use an honest identifier label
    when filename unavailable. Source failures have no invented upload attempt count.
    Inspector uses attemptHistoryPage across cycles; unknown/held work offers recovery
    rather than a misleading Retry. Map cause/code to a relevant safe remedy.
12. Long-lived observers must not hold self across an infinite stream; explicit
    shutdown/cancel/join owns them. Thumbnail callbacks marshal to MainActor, reject
    stale/cancelled generations, cancel prior requests, clear off-screen image and
    account decoded pixel bytes. Keep <=100/16 MiB cache, visible rows/local previews
    only. Export into a canonical app-owned protected/excluded directory, remove
    partial failures and after share/dismissal, and bound stale-export cleanup on
    next startup; never delete unrelated files or an active share's file.
13. Keep actual network/background/idle-cleanup integration pending P6; preserve
    honest unavailable controls and never clear a real system gate from preferences.
    Do not remove background transport inventory guards or claim background support.
