## Implemented correction / prepared replacement

TDLibSession exposes an optional dispatch acknowledgement after the existing native
send and pending/deadline registration. Startup uses a structured child request to
queue the initial network gate, awaits that dispatch acknowledgement, then sends
parameters. Both native responses are awaited with bounded deadlines and cancellation;
no fire-and-forget network failure, extra native client or database deletion. Policy
updates cache desired state until initialization, serialize native application with
ownership rechecked after actor suspension, and apply the latest gate after startup.
A genuine final authorization query updates the UI. Native application version now
comes from the app plist so later visible version changes cannot leave it at 2.0.

Visible provider rejection messages include safe numeric codes. The event text also
includes the closed safe failure description rather than referring to an unseen code.

Service evidence: raw paste.rs POST returned 400 from this Mac using both text/plain
and the documented curl content type with a non-private 57-byte build identification.
A small /web POST returned 303; bare-ID GET retrieved exact bytes and DELETE returned
200. The .txt URL is rendered HTML on paste.rs, not raw text. Both 256 KiB URL-encoded
and multipart submissions returned 500; an 8 KiB URL-encoded submission also returned
500. Larger report support is therefore not established; do not label that route fixed.
No personal user attachment or credential was posted during these checks.

The dpaste.com replacement was initially prepared pending destination approval.
User subsequently explicitly approved the move; verification evidence follows below. Automatic approval review
rejected the attempted compiler-log upload because the existing approval named

Prepared implementation sends one capped form POST, specifies User-Agent and seven-day
expiry, spaces all requests by at least 1.1 seconds after completion, validates HTTP
201 and the exact HTTPS host/ID, then verifies raw .txt retrieval against the original
body before returning a link. It never automatically retries or switches hosts.
The UI names the destination and expiry. Existing local file export remains available.
Official contract: https://dpaste.com/api/ ; https://dpaste.com/help/ ; https://dpaste.com/terms/
